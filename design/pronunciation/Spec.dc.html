发音与音标 · 界面与交互规范
对应 发音与音标学习DESIGN.md 1.0 的 P0 范围（§32）。令牌全部取自 core/designsystem/Color.kt，没有为这个模块新增颜色。这份稿子描述目标形态，不代表已实现——现状看 ROADMAP.md 和代码。
1 · 入口与它不碰的东西
入口挂在学习页，排在听力训练之后，是第七个入口。它不进今天的必做流程，理由和听力训练一样：这是一个可以完全不碰也能把每日闭环走完的模块，塞进必做会把 10～15 分钟撑爆。 底部一级导航仍然是四项，本模块不占位。
按设计文档 §2.2 和 §37，本期只共享基础设施，不共享学习状态：不写全局 ErrorRecord、不进 FSRS、不进 Daily Learning Queue、不改 Mastery、不动 CEFR，词卡里的音标也不跳到这里来。 界面上这意味着三件事：本模块的结束页不出现「今日进度 +1」；首页的推荐只从本模块自己的队列里出；词卡上的 /ɡrɪp/ 保持不可点。

3 · 双轨评分怎么显示
设计文档 §14.3 说数据层必须保留听辨和发音两个方向。界面上把这条执行到底：任何一屏都不出现把两者合成的单一分数，包括首页、总览图块和结束页。 Profile 顶部那两个数字（听得出 14 / 发得出 6）是计数，不是平均分，它存在的意义正是让这两条线的差距可见。
规则
界面上长什么样
样本 < 8
百分比用 outline #79747E，进度条降到 outlineVariant，后面挂一句「才练了 N 次，这个数还不作数」。不标红、不进推荐队列、不排优先级。
单次异常
不改变任何状态标签、不改变排序、不触发降级文案。界面对这条的唯一表现是：分数没有跳。
连续低分
连续 5 次落在低区才改状态。改的时候也只改状态标签和推荐顺序，不弹任何提示。
降级
题目变简单，文案不出现「退步」「掉下来了」「重新开始」。降级在界面上必须是静默的。
一次分数的权力
评分卡上「这次 78」旁边必须同时出现最近 5 次，让单次分数在上下文里被读。不允许只显示一个数。
4 · 一屏只问一件事
答题态（Perceive 01、Hints 01）上不允许出现：音标、发音位置说明、例词、分数、上一题结果、下一步推荐、任何形式的答案提示。 顺序永远是先答 → 再给正确答案 → 再给解释。答错屏的主按钮是「再听一次这两个」而不是「下一题」：错了那一刻是这组对比最值得听的时候，直接推进等于把这一次错误浪费掉。
5 · 音频
同一组对比不能长期只用一个声线，否则用户学会的是「适应这个 TTS」而不是分辨这个音（§24.1）。变化维度按优先级：speaker → 词 → 语境 → 语速；只改音量不算变化。 replayCount 每题都记，它既是难度证据也是提示阶梯 Level 1 的来源。初级不限制重放次数，进阶逐渐收紧，但永远不禁止重放——听不清就是听不清。
6 · 复用现有语音链路（这是硬约束）
设计文档 §25.1 和 ARCHITECTURE.md §0 同向：本模块的「独立」是产品意义上的独立，不是可以另起一套语音基础设施。 TTS、录音、发音评估一律走既有的 SpeechController → SpeechProvider → AzureSpeechProvider，密钥沿用设置页里那一份 Azure 配置，本模块不新增密钥入口。 禁止出现 PronunciationSpeechService / AudioEngine / VoiceManager 这类平行抽象。
播放状态机和并发不变量以 语音服务DESIGN.md 为准：同一时刻只有一个音源在响，进入录音前必须先停掉正在播的 TTS。 Perceive 里的「再放一次」和 Produce 里的「听我刚才那次 / 听标准的」都受这条约束。
7 · Material 3 组件映射
听辨选项 = OutlinedCard（未选）→ 反馈态换 2dp 描边 + container 底色，不用 RadioButton：整块是触摸目标，高度 72dp。
总览分段 = SingleChoiceSegmentedButtonRow。音位图块 = Card，未学态用 1dp 虚线描边而不是灰底。
提示面板 = 页面内的 Surface（surfaceContainer，顶部 16dp 圆角），不是 ModalBottomSheet：题目必须一直可见，遮住题目再给提示没有意义。
录音按钮 = 88dp 的 FilledIconButton，长按录音 / 点击开始两种都支持。波形 = 自绘 Canvas，不引依赖。
失败提示 = 行内 Surface，不是 Snackbar（会挡住底部主按钮）。
8 · 无障碍
状态一律文字 + 图标 + 进度三重表达，颜色不是唯一信息（§29.1）。「稳了 / 能听辨 / 在练发音」各有自己的图标形状，色盲用户靠形状也能读。
IPA 符号必须带 contentDescription——TalkBack 念 /ɪ/ 会念成乱码，语义标签写「短音 i」。
所有触摸目标不小于 48dp；选项卡 72dp。字体放大到 200% 时，音位图块允许换行成两列，不允许截断状态文字。
每道听辨题进入时自动播放一次，同时发 liveRegion 播报「已播放，请选择」，纯听障用户能知道这一题不适用而不是卡住。
9 · 文案边界
按 UI_BRIEF.md §2.1，本模块里可以随语气变皮的只有：首页那句「音标是标签…」、结束页标题、空状态。
任何语气下都照直说的：分数、样本数、状态标签、发音动作说明、错误原因、权限与隐私说明、音标本身。发音指令写错会让用户练错肌肉，这里没有幽默的位置。
「今天到这里」和「再练 2 分钟」在结束页是平等选项，前者不带愧疚、不出现积压数字。录音隐私那句（「录完就评分，评完就删」）必须在每个录音屏都出现，不能只在首次说一遍。
10 · 建议的实现顺序
1. 音位与对比的静态数据 + SoundCard + TTS 播放（不需要评分服务就能做完）。
2. Perceive 二选一四态 + PerceptionAttempt 落库 + 听辨分。
3. Main 首页与模块内推荐队列（40 / 25 / 20 / 15 的配比先写死）。
4. Produce 单词跟读 + Azure Pronunciation Assessment + States 的四种失败态。
5. Profile + 置信度 + SessionEnd 的前后对比。
6. Onboarding 摸底（放在最后：它依赖前面所有题型都已经能跑）。
7. Hints 提示阶梯与自适应难度。
句中最小对立、多 speaker、Same / Different、短语跟读属于 P1，先不做。
11 · 我做的假设 · 需要你拍板的
假设：入口挂在学习页第七位、不进今天必做流程。设计文档只说了「独立入口」，没说挂在哪一级；按 UI_BRIEF.md §4.2 的既有分工，学习页是自由学习入口的容器，这里最合适。
假设：音位、对比、最小对立词表是随包的静态数据（assets），不走 AI 生成。发音描述和中文误读说明是这个模块的知识基座，让模型每次现编会出现同一个音两种说法。这也意味着它不需要新的 AI 契约。
假设：例词和句子的音频由现有 Azure TTS 现合成并缓存，不预置音频文件。
假设：「稳了」只是模块内状态，总览页的图例里明说了这一点，避免用户以为它等于全局掌握。
需要你定 1：这个模块要四张新表（音位、对比、听辨记录、发音记录）加一次 Room 迁移。按 AGENTS.md §2，加表要先走架构变更请求——这份稿子只画了界面，没有替你批准这件事。要不要开这个口子，是先做的决定。
需要你定 2：多 speaker 在设计文档里是 P1，但 Perceive Level 3 的价值几乎全在换声线上。只有一个声线时，听辨分到 85% 以上就没什么意义了。是把多 speaker 提到 P0，还是接受第一版的分数在高区不准？
需要你定 3：摸底放在最后实现（顺序第 6 条），意味着第一版进来的用户看不到画像，首页推荐得有个冷启动兜底。现在按「先推最常见的三组对比」画的，没画专门的冷启动屏。
