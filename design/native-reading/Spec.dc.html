1 · SPAN 视觉（设计文档 §20.1）
masteryClass
正文里长这样
规格
mastered
不追求 perfect prediction
不加任何标记。已经会的词就该像正文一样读过去。
review
准确地 predict demand
1dp 点线下划线，outlineVariant #CAC4D0。可点，但几乎不抢眼。
target
而是 leave room for error
1.5dp 实线下划线，primary 40% #B9A9DE。第三次出现后按 mastery 撤掉（§10.6 scaffolding fade-out）。
grammar
as long as the system can recover quickly
整块一个可点区域，底色 surfaceContainer #F3EDF7，圆角 4dp。不许拆成几个词各点各的。
incidental
这类系统的 latency 很难压下去
技术词 / 专名。不加标记，算进英语表层比例，不算学习目标。
设置里「给目标词加轻提示」关掉后，review / target / grammar 全部退成无标记，点击行为不变。颜色不是唯一线索：所有 span 都可点、都能长按看原文，视障用户走的是语义标签而不是下划线。
2 · 语言岛，不是词汇碎片（§5）
不要这样
这个 system 通过 reduce 用户的 waiting time 来 improve experience。
每个词都对，读起来全是碎片。排版上会出现一行里 3 次以上语言切换。
要这样
这个系统真正想降低的，并不是 actual waiting time，而是人对等待的不确定感。
一个完整语义块切过去，中文句子结构不断。渲染约束：同一行最多 2 个 span，相邻 span 至少隔 8～20 个中文字符。
3 · 手势（§12.1、§13）
单击 span
升起 Bottom Sheet，原页面留在上面可见。绝不整页跳转——那会把阅读打断。
长按 span / 整句
就地显示原来的中文，不开面板。这是最低成本的 rescue，必须比查释义还快。
Sheet 里点「看详情」
才进已有的单词页 / 语法页，走 knowledgeId。词库里还没有的表达先做临时项，点「加进复习」才落库。
短时间内连点多个 span
正文里插一条行内卡片问要不要降档，只对这一篇生效，不动设置。用户说「不用」之后本篇不再问。
