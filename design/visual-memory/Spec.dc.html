单词视觉记忆图片 · 视觉与交互规范
对应 单词视觉记忆图片DESIGN.md 的 MVP v1（§58）。令牌全部取自 core/designsystem/Color.kt，没有为这个功能新增颜色，也没有新增层。
1 · 图片区在词卡里的位置
设计文档 §45 的示意图把图放在最上面，这里没有照抄，理由是同一份文档的 §63：图片可能不存在，也可能加载失败。图在最上面时，收起图片区会让整张卡向上跳一屏，词头位置每次打开都不一样。所以顺序是词 → 音标 → 词性释义 → 图 → 例句 → 怎么记：词头位置永远固定，图片区出现与否只影响它自己下面的内容。
规格
取值
图片尺寸
宽度撑满内容区（屏宽 − 32dp），固定 16:9，ContentScale.Crop。不按原图比例变高，否则每张卡高度都不一样。
圆角 / 背景
12dp；加载前后底色 surfaceContainerHigh #ECE6F0，避免白闪。
上方标签
「这个词义看起来是这样」，labelMedium / onSurfaceVariant，带 16dp 图片图标。这句话是在提醒用户图跟的是当前词义，不是这个单词。
来源行
两行 bodySmall / outline #79747E：「来自网络搜索 · {publisher}」「图片版权归原站所有 · 点开看出处」。整行可点，打开 sourcePageUrl。
换一张
OutlinedButton，40dp 高，和来源行同一行右侧。这是次操作，不能做成 filled。
⋯
36dp IconButton（触摸区 48dp）。里面放：图片不相关 / 太抽象 / 看不懂 / 质量差 / 不想看到这张，对应 ImageFeedbackReason。
字不画在图上
单词、释义一律在图外（设计文档 §68）。这样图片线索、词形线索、词义线索可以分别撤掉，SRS 的撤图才有意义。
2 · 状态机
状态
界面
怎么进来的
Loading
16:9 的 #ECE6F0 块 + 24dp 进度圈 + 一句「正在给「{词义}」这个意思找图」。
缓存没命中，且这个词义判定为可视觉化。
Ready
图 + 来源行 + 换一张 + ⋯。
Top 1 的 overall ≥ 0.70。
Unavailable
收成一行 16dp 图标 + 「这次没找到能说清这个意思的图」+ 文本按钮「再找一次」。不留空框。
搜完 primary + 2 个 fallback 仍无合格候选，或全部候选被硬过滤掉。
NotVisualizable
整块（含上方标签）不渲染。用户在 ⋯ 里仍可主动「找张图试试」。
visualizability < 0.40，或路由判定为 none。
Failed
静默换成 Top 2 / Top 3，并在图下方给一条 #FCEAC8 提示条，4 秒后自动收起。三张都挂 → 落到 Unavailable。
外链图 404、域名拒绝、URL 过期。
五种状态都不阻塞词卡：词、音标、释义、例句、怎么记先渲染，图片区自己异步填。加载失败不弹 toast、不打断自评。
3 · 哪儿出现图、哪儿不出现
场景
图片
第一次学这个词
正面就给图，图在词上方（Fade 画板第一档）。
前两次到期复习
同上。
再往后的复习
正面只给词形，图退到答案面当确认。
已经熟了（中译英打字档）
完全不出现，也不留入口。
记录 → 单词详情
永远显示。这是查阅，不是复习，不受撤图影响。
母语阅读点词 Bottom Sheet
只显示已缓存的图。缓存没有就不显示，也不在这里现搜——点开等三秒会毁掉阅读节奏。
拼写训练、听力、情景演练
不出现。这些环节考的是形和音，给图等于泄题。
4 · 什么时候去搜
打开词卡的那一刻不该触发 LLM → Brave。三个触发点：添加单词时（生成学习卡的同一次后台任务里顺手做）、文章生成完成后（只给本篇新目标词和重点复习词预取，熟词不预取）、用户点「换一张」或「再找一次」。冷启动没赶上的，才在词卡里现搜，并走 Loading 态。
Brave API Key 只在后端。客户端拿到的是已经排好序的 Top 3 及其缩略图地址，不自己拼搜索请求。
5 · 无障碍
项
要求
contentDescription
用后端返回的 visualTarget 译成中文，例如「一只手紧紧握住金属把手」。不要用「图片」「单词配图」这种没信息的描述，也不要直接念 title（那是网页标题，经常是广告文案）。
图不是唯一线索
图能表达的东西，释义和例句里必须也有。看不见图的用户不会少拿到任何信息。
触摸区
换一张 40dp 高、⋯ 48dp 触摸区；候选列表每项 ≥ 104dp 高，缩略图和文字整块可点。
大字体
来源行两行在 200% 字号下换行，不截断；图片高度不随字号变。
深色主题
图上不叠任何半透明遮罩——压暗一张照片只会让它更难认。图片区底色换成 surfaceContainerHigh 的深色值即可。
6 · Material 3 组件映射
图片区 = Box(Modifier.aspectRatio(16/9f).clip(RoundedCornerShape(12.dp))) + Coil AsyncImage（placeholder/error 都走上面的状态机）。
换一张抽屉 = ModalBottomSheet，候选项 = 带 2dp primary 描边的 Card（选中）/ 1dp outline 描边（未选）。
⋯ 菜单 = DropdownMenu。失败提示条 = 行内 Surface，不是 Snackbar（Snackbar 会挡住底部自评）。
7 · 实现顺序
1. 词卡里的图片区五态 + 来源行（后端先返回假数据也能做）。
2. 后端 POST /vocabulary/:senseId/image/search：可视觉化判定 → 生成 1 主 2 备搜索词 → Brave count=20, safesearch=strict → 基础过滤 → 存 Top 3。
3. 添加单词时预取 + 缓存按 senseId 存。
4. 换一张抽屉 + 记录换图行为。
5. SRS 撤图三档。
6. 阅读 Bottom Sheet 读缓存。
7. ⋯ 反馈原因。
先不做 Vision 重排、生成图 fallback、OCR、多义辨析题——那些等换图率的数据出来再说。
8 · 我做的假设 · 还需要你定的
假设：图片只显示 Brave 的缩略图（约 500px 宽，走它的图片代理），不下载原图、不进自己的 CDN——这是设计文档 §33/§35 的版权口径的直接后果，也意味着离线时看不到图，离线走 Unavailable 态。
假设：「这个词不用配图」是按词义记的用户偏好，不影响别人，也不改全局 registry。
假设：多义辨析题（Senses 画板下半部分）只在一个词同时在学两个词义时出现，属于 v1.5，先画出来占位。
需要你定 1：词卡里默认展开图片，还是默认收起、点一下「看图」再展开？现在按默认展开画的——图的价值在第一眼，收起等于没有。但这会让每张卡多约 220dp。
需要你定 2：没有后端的时候（这个仓库目前是纯客户端 + 用户自己的密钥），Brave Key 放哪儿。设计文档说绝不能放客户端，但当前架构里没有「你的后端」这一层。要么用户自己填 Brave Key 并接受风险，要么这个功能等有服务端再上。
需要你定 3：示例图现在是矢量占位，不是真实搜索结果。真图接进来之后，需要复看一遍构图裁切（16:9 居中裁会不会把手裁掉）。
